Knowledge is a progressive, index-first document tree.

- Start with `knowledge/project/navigation/index.md` for code paths and `knowledge/project/index.md` for project decisions and diagnostics. Read global knowledge only when the task needs cross-project guidance.
- Inspect `knowledge/global/agent-lessons.md` early when reusable Agent pitfalls may apply. Follow relevant links only; do not enumerate unrelated knowledge.
- Treat `knowledge/pending-updates/index.md` and stale/wrong entries as revision requests, not current facts.
- Before the final response, perform one Knowledge closeout. Submit a candidate or revision immediately when the Turn produced durable reusable material. Submit helped/stale/wrong feedback only when an existing entry materially affected the work. If nothing durable changed, do not invent a submission.
- Knowledge changes are proposals. Use a new revision only after the API reports it verified; a pending proposal is not current guidance.
- Put reusable cross-project reference material under General Knowledge and reusable Agent pitfalls under Agent Lessons. Rules that must always apply belong in a Prompt or selected Skill.
